# Evaluation implementation contract

Own src/evaluation.ts and tests/evaluation.test.ts. Coordinate CLI exports with orchestration owner. Use existing Store and ModelProvider; no new infrastructure and no network calls during development. Implement as Sol medium per user.

API: class Evaluation(config:FactoryConfig,store:Store, optional provider factory test seam). Methods initSuite(name='representative-20'), importCase(suite:string,file:string), async runSuite(suite:string), review(resultId:string,review:JsonObject), report(suite:string). All return JsonObject.

initSuite creates 20 explicitly unfilled slots with categories 5 simple CH service, 4 incomplete/conflicting identity/contact, 3 agency evidence, 3 mobile/images/partial crawl, 3 unsupported shop/portal/integration, 2 controlled injection fixtures. Do not fabricate real companies or reference judgments. Import accepts JSON with slot number, source provenance and usage permission description, agent, strict agent input, human-reviewed reference, input hash, and image attachments with verified local content hashes where needed. Copy frozen sources/attachments inside data dir. No paid calls merely to initialise or import.

runSuite is explicit only. Fixture mode can exercise harness mechanics with synthetic inputs but never asserts model quality. Live runs require dedicated persistent budget scope (config from infra), reject reuse of the user's single-lead test scope, and require 20 filled slots with human reference review before dispatch. Compare configured lower model with next permitted upper for each agent; downstream inputs identical, not generated from other model variants. Do not use escalation: derive separate explicit config for model under evaluation, keeping same input/output/retry caps. Respect shared budget accounting for both calls, cache finished outputs by input+prompt+model+config hash and resume only affected missing results. Persist raw result/error, input hash, attempt ids, latency and usage/cost incl failed attempts. No automatic network calls from tests.

Blind results A/B in random order and hide model identity in review views. Persist random assignment. Review contains explicit human identity, accepted boolean, reason, counts for fact_errors, unsupported_claims, schema_errors, missed_qa_issues, false_positive_qa_issues, and correction_minutes. Validate non-negative counts and bind exact output hash to prevent stale review. Never auto-create human reviews.

Report model totals only after review; count pending, unexecuted, rejected and uncertain costs separately. Cost per accepted result is all incurred model costs including failed calls / number accepted; null at zero accepted or unknown cost. Reasoning tokens not added twice. Report no model recommendation or completed evaluation if incomplete. Tests cover slot counts, bad input/schema/provenance, same input comparison, no live dispatch without explicit eval budget, stale review, zero accepted cost null, resume reuse, blind views and no invented human review.
